# Infographic and Diagram

Choose the diagram's job before drawing: sequence, responsibility, relationship, lifecycle or deployment boundary.
Verify the source relationships and name the entities consistently with the surrounding content.

- Keep one main reading direction and label arrows whose meaning is not obvious.
- Distinguish data flow, control flow and entity joins rather than using one ambiguous arrow for all three.
- Show the consequential validation, failure or access boundary when it explains system behaviour.
- Route connectors behind nodes; avoid crossings through labels and implied links unsupported by the source.
- Split an overcrowded architecture into overview and detail instead of shrinking text.
- Keep a legend only when the notation actually needs one, and avoid colour-only meaning.

Follow the host format skill's diagram tooling rules.
Prefer native editable shapes for simple Office diagrams, Mermaid for supported text renderers or an appropriate graph/layout tool for complex topology.
Check the exported result at its actual display/print size, including arrowheads and label contrast.
