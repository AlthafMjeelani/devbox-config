## Standard User Manual Creation Skill

## Recommended Prompting Workflow

## Goal
Create a professional, clear, and user-friendly manual for any software, mobile app, web app, or system.

## Writing Style
- Use simple and clear language.
- Write for normal users, not developers.
- Avoid technical explanations unless required.
- Keep instructions step-by-step.
- Use short sections with proper headings.
- Add tables where useful.
- Add screenshot placeholders for important screens.
- Maintain a formal and clean documentation style.

## Standard User Manual Structure

The manual should include these sections:

1. Cover Page
2. Document Information
3. Introduction
4. System Overview
5. User Roles and Access
6. System Requirements
7. Getting Started
8. Login and Account Access
9. Dashboard / Home Screen
10. Module-wise User Guide
11. Create / Add New Record
12. Edit / Update Record
13. Delete / Cancel / Remove Record
14. Search, Filter, and Sort
15. Reports and Export
16. Notifications and Alerts
17. Profile and Settings
18. Common Workflows
19. Error Messages and Troubleshooting
20. FAQ
21. Support and Contact
22. Terms, Policies, and Notes
23. Appendix

## Module Documentation Format

For every module, use this structure:

### Module Name

#### Purpose
Explain what this module is used for.

#### How to Access
Explain where the user can find this module.

#### Screen Overview
Explain the main fields, buttons, tabs, and actions available on the screen.

#### Step-by-Step Usage
1. Open the module.
2. Select or enter the required details.
3. Click the required action button.
4. Review the result.
5. Save, submit, confirm, or cancel based on the workflow.

#### Available Actions
List all possible actions such as:
- Add
- Edit
- Delete
- View
- Search
- Filter
- Export
- Print
- Submit
- Approve
- Cancel

#### Important Notes
Mention validations, restrictions, required fields, permissions, or warnings.

#### Screenshot Placeholder
[Add Screenshot: Module Screen Name]

Below each screenshot placeholder, explain:
- Screen purpose
- Main fields/buttons
- User actions
- Important notes

## Common Workflow Format

Use this format for end-to-end workflows:

### Workflow Name

#### Purpose
Explain why the user performs this workflow.

#### Steps
1. Step one.
2. Step two.
3. Step three.
4. Final step.

#### Expected Result
Explain what should happen after completing the workflow.

#### Possible Errors
Mention common errors and how to solve them.

## Troubleshooting Format

Use this table format:

| Issue/Error | Possible Reason | Solution |
|---|---|---|
| Cannot login | Wrong username or password | Check credentials and try again |
| Page not loading | Network issue | Check internet connection |
| Data not saving | Required field missing | Fill all mandatory fields |
| Permission denied | User has no access | Contact admin |
| File upload failed | Invalid file type or large file | Upload supported file format |

## FAQ Format

Use simple question and answer format:

### Q: Question here?
A: Short and clear answer here.

## Output Requirement

When generating a user manual:
- Use proper headings and numbering.
- Keep the language simple.
- Add tables where helpful.
- Add screenshot placeholders.
- Avoid unnecessary technical details.
- Make the manual easy for a non-technical user to follow.
